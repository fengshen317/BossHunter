# 问答流程测试用例

## 一、测试目标

覆盖 AI 助手当前的主要问答分支：

- 普通问答与上下文问答
- 本地岗位数据库查询
- 联网搜索与公司研究
- 信息缺失时的澄清流程
- 多轮补全意图
- 复杂任务规划
- HR 回复草稿与高风险操作审批
- 取消待执行操作

| 编号 | 测试输入 | 预期意图 | 预期路由 | 预期执行路径 |

| Q20 | 搜索岗位并给我评分 | `complex_task` 或多步骤意图 | `planner` | 岗位采集 → 初筛 → AI 评分 → 返回结果 |

| Q22 | 发送所有高分岗位的招呼语 | `greeting_send` | `clarification` 或 `capability` | 查询岗位 → 人工选择/确认 → 低频发送任务 |
| Q23 | 监听 HR 回复 | `reply_monitor` | `capability` | 启动 monitor 任务 |
| Q24 | 自动回复所有 HR 的问题 | `reply_send` 或 `reply_monitor` | `clarification` 或 `capability` | 确认范围 → 生成回复 → 按配置自动回复或人工确认 |
| Q25 | 不用了，取消刚才的操作 | `cancel` | `direct` | 取消待确认操作，不启动任务 |

## 三、多轮澄清测试

### Q26：岗位搜索补全

```text
第 1 轮：帮我搜索岗位
预期：clarification，询问岗位关键词和城市

第 2 轮：Python
预期：补全 keywords，若仍缺城市则继续澄清

第 3 轮：上海
预期：补全 city，进入 job_search 执行
```

### Q27：岗位评分补全

```text
第 1 轮：帮我给岗位打分
预期：clarification，询问具体岗位

第 2 轮：刚才列表里的前 5 个
预期：补全 job_ids，进入 job_score
```

### Q28：HR 回复草稿补全

```text
第 1 轮：帮我回复 HR
预期：clarification，询问具体会话或 HR 原话

第 2 轮：他说“方便发一份简历吗”
预期：生成 reply_draft，并要求人工确认
```

## 四、高风险操作测试

### Q29：发送招呼语必须审批

```text
输入：帮我发送招呼语

预期路径：
识别意图 → 匹配 send_greetings → 生成审批卡 → 等待人工确认
```

验证要求：

- 未确认前不能启动发送任务
- 审批卡应支持选择岗位
- 应支持确认、编辑或拒绝
- 拒绝后不能产生发送记录

### Q30：发送 HR 回复必须审批

```text
输入：帮我回复 HR：您好，我考虑一下

预期路径：
识别为 send_hr_reply → 生成回复草稿 → 展示审批卡
→ 用户可编辑/确认/拒绝 → 确认后启动 reply 任务
```

验证要求：

- 回复内容可以在审批阶段编辑
- 未确认前不能调用发送任务
- 确认后只能启动一次任务
- 重复提交相同 `action_id` 应被拒绝

### Q31：恢复审批任务

```text
第 1 轮：发送这几个岗位的招呼语
预期：返回待审批状态

第 2 轮：确认发送
预期：恢复 LangGraph checkpoint → 校验 action_id
→ 校验 selected_item_ids → 启动任务 → 返回 task 状态
```

## 五、建议记录的实际结果

每条用例至少记录以下字段：

```text
1. intent.intent_type
2. intent.mode
3. intent.confidence
4. intent.missing_fields
5. 最终 route
6. 是否调用 job_database
7. 是否调用 web_search
8. 是否进入 planner
9. 是否生成 approval
10. 是否启动后台任务
11. 最终 assistant message_type
12. 意图识别耗时
13. 总响应耗时
```
