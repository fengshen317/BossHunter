# Agent 生产基础设施

BossHunter 使用 PostgreSQL 作为唯一持久化数据库，Redis 作为唯一运行时协调设施。任一组件不可用时服务启动失败，不再回退 SQLite 或进程内协调器。

## 组件职责

| 组件 | 事实边界 |
| --- | --- |
| PostgreSQL | 岗位、历史、会话、Checkpoint、Agent Run、DAG 步骤、Observation、审批和制品引用 |
| Redis | 会话锁、取消信号和实时事件流；不得作为最终事实来源 |
| Dramatiq | 执行显式注册的后台任务；发送类任务禁止自动重试 |
| S3 / MinIO / 本地目录 | 保存大于上下文预算的工具结果和生成文件 |

## PostgreSQL

1. 创建数据库。
2. 按编号依次执行 `migrations/postgresql/` 下的全部迁移：`001_agent_runtime.sql`、
   `002_business_data.sql`、`003_semantic_layer.sql`、`004_context_memory.sql`、
   `005_workbench_task_stage.sql`。`003` 建立问数所需的结构化岗位事件、状态触发器和分析视图；
   `005` 为工作台任务补上流程阶段字段（前端进度条不再解析日志文案）。
3. 设置 `database.url`，例如：

```yaml
database:
  url: "postgresql+psycopg://user:password@127.0.0.1:5432/bosshunter"
```

旧数据可使用 `scripts/migrate_sqlite_to_postgresql.py` 和 `scripts/migrate_checkpoints_to_postgresql.py` 幂等迁移。

## Redis 与取消

```yaml
runtime:
  redis_url: "redis://127.0.0.1:6379/0"
  redis_required: true
```

Redis Key 使用 `bosshunter` 命名空间。Redis 故障时服务快速失败，避免多个实例失去锁、取消信号和事件一致性。

取消接口：

```text
POST /api/assistant/runs/{run_id}/cancel
```

DAG 调度器会在每个并行批次开始前检查取消信号。正在运行且无法安全中断的外部 SDK 调用会先完成，之后不再启动新节点。

## Worker

后台任务必须通过 `register_task()` 注册，Worker 不接受任意模块或函数路径。`send_greetings`、`send_hr_reply` 和 `run_pipeline` 默认禁止自动重试，防止外部动作重复发生。

## 制品存储

本地默认：

```yaml
artifacts:
  backend: "local"
  local_path: "./data/artifacts"
```

S3/MinIO：

```yaml
artifacts:
  backend: "s3"
  bucket: "bosshunter-private"
  endpoint_url: "http://127.0.0.1:9000"
```

访问密钥使用环境变量 `BOSSHUNTER_S3_ACCESS_KEY` 和 `BOSSHUNTER_S3_SECRET_KEY`。工具结果超过 16KB 时保存为私有制品，Observation 只保留摘要和 `data_ref`。
