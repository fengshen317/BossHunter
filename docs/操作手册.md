# BossHunter 操作手册

> 适用版本：BossHunter 2.0  
> 面向对象：使用 BossHunter 完成个人求职流程的用户  
> 使用原则：低频、短期、人工确认、随时可停止

## 1. 手册目标

本手册给出从安装、配置到日常运行和故障恢复的标准操作流程。BossHunter 是个人求职效率工具，不是无人值守的批量投递系统。

使用前应接受以下边界：

- 仅使用本人的账号、简历和求职信息。
- 自动化操作第三方平台存在账号限制或封禁风险。
- 岗位发送前必须人工确认，不应绕过确认步骤。
- 卡片识别、建议回复和简历生成只提供辅助，敏感动作由用户最终决定。
- 达到当天目标、遇到页面异常或风险提示时，应停止任务并人工检查。

## 2. 环境要求

| 项目 | 要求 | 检查命令 |
|---|---|---|
| 操作系统 | Windows、macOS 或 Linux | — |
| Python | 3.11 及以上 | `python --version` |
| Node.js | 22 及以上 | `node --version` |
| 浏览器 | 最新稳定版 Chrome 或 Edge | — |
| AI 服务 | Anthropic Messages 或 OpenAI 兼容接口 | 在配置页验证 |

浏览器中需要登录招聘平台。BossHunter 通过本机 CDP 连接浏览器，不保存平台账号密码。

## 3. 首次安装

在项目根目录执行：

```bash
python -m pip install -e .
bosshunter --version
bosshunter --help
```

如果需要 `xhtml2pdf` 作为 PDF 渲染后备方案：

```bash
python -m pip install -e ".[pdf]"
```

不要把以下文件提交到版本库：

- `config.yaml`
- 真实简历和头像
- `data/` 下的数据库、会话和生成文件
- API Key 或内部服务地址

## 4. 首次配置

### 4.1 启动配置面板

```bash
bosshunter web
```

打开 `http://127.0.0.1:8686`。也可以双击 `start-bosshunter.cmd`，或执行 `bosshunter start` 同时启动独立浏览器和控制台。

### 4.2 必填配置

按以下顺序完成：

1. 上传本人 Markdown 简历，确认不是含“张三”“XX 科技”等内容的示例文件。
2. 设置目标岗位关键词和城市。
3. 设置期望薪资、是否接受实习及一票否决词。
4. 配置 AI 提供商、模型和 API Key。
5. 设置评分阈值、每日发送上限、随机间隔和发送时间窗口。

建议首次使用采用保守参数：

| 配置 | 建议 |
|---|---|
| `search.max_pages` | 1～2 页 |
| `scoring.max_candidates` | 5～10 个 |
| `throttle.daily_limit` | 不高于 10 个 |
| `throttle.interval_min/max` | 保持默认值或更长 |
| `follow_up.enabled` | 首次使用关闭 |
| `monitor.auto_reply_hr_questions` | 关闭 |

API Key 优先通过环境变量提供。若写入 `config.yaml`，不得提交该文件。

### 4.3 连接浏览器

推荐使用：

```bash
bosshunter start
```

首次启动后在独立浏览器中手动登录招聘平台。也可在日常 Chrome 的 `chrome://inspect/#remote-debugging` 中启用远程调试，再执行：

```bash
bosshunter connect
```

只有连接检测通过、平台已登录、真实简历已配置后，才进入正式运行。

## 5. 推荐日常操作流程

### 5.1 每日开始前检查

每次运行前完成：

- 确认当前账号、城市、关键词和简历属于本人。
- 打开招聘平台，确认登录有效且页面无验证码、风控提示。
- 检查发送时间窗口和当天剩余额度。
- 检查 AI 配置可用，API Key 未泄露。
- 先查看历史状态，避免重复操作。

```bash
bosshunter connect
bosshunter status --full
```

### 5.2 分步模式（首次和排障时推荐）

```bash
# 1. 采集少量岗位
bosshunter scrape -k "Python开发" -l 10

# 2. 可选：补全岗位和企业信息
bosshunter reenrich -l 10

# 3. AI 预筛、深度评分并为通过项生成招呼语
bosshunter score

# 4. 可选：补充生成缺失的招呼语
bosshunter greet

# 5. 人工逐项审核
bosshunter confirm

# 6. 只发送已经批准的条目
bosshunter send

# 7. 检查一次 HR 回复
bosshunter monitor --once

# 8. 查看结果
bosshunter status --full
```

审核时重点检查岗位是否真实匹配、公司是否可接受、招呼语是否准确以及是否有不应发送的隐私信息。

### 5.3 一键模式

熟悉分步流程后可以执行：

```bash
bosshunter run
```

一键模式仍必须经过人工确认。不得把“一键”理解为完全无人值守。

### 5.4 Web 工作台模式

```bash
bosshunter web
```

工作台用于配置、查看漏斗、导入岗位、启动或停止任务、审核招呼语、查看监测结果和下载定制简历。

注意：工作台限制高风险后台任务并发；出现“已有任务运行”时，应等待或停止原任务，不要重复启动多个服务规避限制。

## 6. 常用命令

| 目的 | 命令 |
|---|---|
| 检查浏览器 | `bosshunter connect` |
| 采集岗位 | `bosshunter scrape -k "关键词" -l 10` |
| 补全岗位信息 | `bosshunter reenrich -l 10` |
| AI 评分 | `bosshunter score` |
| 生成招呼语 | `bosshunter greet` |
| 重新生成指定招呼语 | `bosshunter greet --job-id <岗位ID>` |
| 人工确认 | `bosshunter confirm` |
| 发送已批准条目 | `bosshunter send` |
| 查看统计 | `bosshunter status --full` |
| 生成指定岗位简历 | `bosshunter resume --job-id <岗位ID>` |
| 单次监测 | `bosshunter monitor --once` |
| 持续监测 | `bosshunter monitor --interval 30` |
| 启动工作台 | `bosshunter web` |
| 一键启动 | `bosshunter start` |

`send --force` 只跳过随机休息日检查，不代表绕过人工确认、时间窗口或其他安全限制。非排障场景不要使用。

## 7. 停止、暂停与恢复

### 7.1 正常停止

- 终端任务：按 `Ctrl+C`。
- Web 任务：点击当前任务的“停止”按钮，等待状态变为“已停止”。
- 浏览器异常、验证码、账号警告或页面结构明显变化时，立即停止。

停止请求可能需要等待当前原子操作结束。不要连续重复点击，也不要直接删除数据库。

### 7.2 停止后的检查

```bash
bosshunter status --full
```

确认最后一个岗位的状态和历史记录。如果不确定消息是否已发出，先在平台聊天页面人工核对，禁止直接重试。

### 7.3 恢复原则

- 采集、评分、生成等步骤可根据数据库状态继续处理。
- 发送失败会按配置退避并有限重试；超过上限后保留为错误状态，需人工检查。
- 服务重启不会自动恢复上次正在运行的 Web 任务。
- 恢复前必须重新检查浏览器连接、登录状态、时间窗口和当天额度。

## 8. 监测、回复与简历

- `monitor --once` 适合人工掌控的日常检查。
- 持续监测应设置合理间隔，并在不需要时停止。
- 系统识别到 HR 问题时，可生成建议回复；发送前应人工确认事实和语气。
- 识别到附件简历请求时，可生成定制简历，但不应自动点击同意、拒绝或发送。
- 下载 PDF 后检查姓名、联系方式、项目事实、页数和排版，再手动发送。
- 不得使用他人的简历或虚构经历。

## 9. 常见故障

| 现象 | 排查与处理 |
|---|---|
| `bosshunter` 命令不存在 | 在项目根目录执行 `python -m pip install -e .` |
| 无法连接浏览器 | 确认浏览器已启动、远程调试已开启、端口未被占用，再执行 `bosshunter connect` |
| 未发现平台页面 | 手动打开平台并登录；处理验证码后再重试 |
| 评分为 0 或 AI 报错 | 检查提供商、模型、Base URL、API Key、余额和请求超时 |
| 没有待确认岗位 | 按 `scrape → score → greet` 检查前序步骤和阈值 |
| 发送未执行 | 检查是否已批准、是否在时间窗口、日限是否耗尽及 HR 在线限制 |
| 连续发送失败 | 停止任务，人工检查页面和选择器；不要不断强制重试 |
| PDF 生成失败 | 检查简历 Markdown、输出目录和 PDF 依赖；必要时安装 `.[pdf]` |
| Web 提示已有任务 | 等待当前任务完成，或正常停止当前任务后再启动 |
| Web 页面与代码不一致 | 在前端目录执行 `npm ci && npm run build`，确认 `dist/` 已更新 |

## 10. 数据与隐私维护

运行时数据默认位于 `data/`：

- `data/bosshunter.db`：岗位、状态和任务记录。
- `data/resumes/`：生成的定制简历。
- `data/history.jsonl`：去重或历史记录。
- `data/browser-profile/`：独立浏览器登录状态。
- `data/artifacts/`：本地制品。

建议定期将必要数据备份到加密位置。备份前停止正在写入的任务。不要通过 Issue、聊天或日志分享 API Key、真实简历、数据库和浏览器配置目录。

## 11. 每日收尾清单

- 停止持续监测和不再需要的后台任务。
- 查看当天发送、回复、失败和待处理数量。
- 人工核对异常状态和待回复消息。
- 关闭不再使用的调试浏览器或服务。
- 不为“刷数量”临时调高频率、扩大时间窗口或跳过确认。

## 12. 使用完成标准

一次操作周期满足以下条件即可结束，不应继续无限执行：

- 当天计划岗位已完成筛选和人工确认。
- 已批准岗位已在安全限制内处理，失败项已有明确记录。
- HR 回复和简历请求已分类，敏感动作已留给人工决定。
- 没有遗留的持续任务，状态可在工作台或 CLI 中追溯。
- 达到当天上限、出现风控信号或收益明显下降时立即收尾。
