# BossHunter 故障排查

排障时先停止发送和持续监测任务，再保留完整错误输出。不要通过反复强制执行来判断问题是否消失。

## 1. 快速诊断顺序

```bash
python --version
node --version
bosshunter --version
bosshunter connect
bosshunter status --full
```

随后确认 PostgreSQL 可连接、招聘平台已登录、`config.yaml` 使用了正确路径，并查看终端中最早出现的异常。

## 2. 安装与命令

### `bosshunter` 命令不存在

```bash
python -m pip install -e .
python -m bosshunter.main --help
```

如果模块命令可用而控制台命令不可用，通常是虚拟环境未激活或 Python 的 Scripts 目录不在 `PATH`。

### Python 版本不兼容

当前项目要求 Python 3.11 或更高版本。确认创建虚拟环境时使用了正确解释器，然后重新安装依赖。

### Node.js 不可用

内置 Browser Runtime 需要 Node.js 22 或更高版本。安装或升级后重新打开终端，再执行 `node --version`。

## 3. PostgreSQL

### 提示必须配置 `database.url`

从 `config.example.yaml` 复制 `config.yaml`，填写 PostgreSQL 地址。SQLite 地址和本地 `.db` 路径不再受支持。

### 连接被拒绝或认证失败

依次检查：

1. PostgreSQL 服务是否启动。
2. 主机、端口、数据库名、用户名和密码是否正确。
3. 密码中的特殊字符是否已进行 URL 编码。
4. 数据库用户是否具有连接和建表权限。

可先使用原生客户端验证：

```bash
psql "postgresql://user:password@127.0.0.1:5432/bosshunter" -c "select 1;"
```

### 缺少表或字段

按编号检查并执行 `migrations/postgresql/` 中尚未应用的迁移。不要只执行最新文件；后续迁移依赖前面的表结构。

## 4. 浏览器与 CDP

### 无法连接 Browser Runtime

- 确认 Chrome/Edge 已启动，且远程调试已开启。
- 优先使用 `bosshunter start`，由程序选择浏览器和端口。
- 检查 `browser.proxy_port` 与 `chrome_ports` 是否被其他程序占用。
- 如果使用手动浏览器，先打开招聘平台并完成登录，再执行 `bosshunter connect`。

### 未找到平台页面或登录失效

在被连接的同一个浏览器用户目录中打开平台页面，人工处理扫码、验证码和风险提示。不要尝试自动绕过验证码或平台风控。

### 页面更新后采集或发送失败

平台选择器可能已经变化。立即停止发送，保留页面截图、失败时间和不含隐私的日志，然后提交 Issue。不要连续重试或临时提高频率。

## 5. AI 服务

| 现象 | 处理方式 |
|---|---|
| 401 / 403 | 检查 API Key、Auth Token、服务权限和 Base URL |
| 404 | 检查 Base URL 是否重复或缺少 `/v1`，以及模型名是否存在 |
| 429 | 降低评分/招呼语并发，等待配额恢复 |
| 5xx | 保留默认退避；持续失败时检查服务状态 |
| 请求超时 | 适当提高 `ai.request_timeout`，检查网络和模型响应速度 |
| 模型不匹配 | 查询兼容服务的 `/v1/models`，填写服务实际返回的模型名 |

不要把完整请求、真实简历或 API Key 粘贴到公开 Issue。

## 6. 任务状态与发送

### 没有待确认岗位

按顺序检查 `scrape → reenrich（可选）→ score → greet → confirm`。评分阈值、硬过滤规则或候选上限可能使岗位未进入确认阶段。

### `send` 没有执行

确认岗位已经人工批准，并检查：

- 当前时间是否位于 `send_windows`。
- 当日发送额度是否耗尽。
- 是否启用了“仅 HR 在线时发送”。
- 是否处于随机休息日。
- 浏览器连接和平台页面是否正常。

`send --force` 只跳过随机休息日检查，不绕过人工确认或其他安全限制。

### 不确定消息是否已经发出

先在平台聊天页面人工核对，再决定是否重试。重复发送比漏发更难恢复。

## 7. Web 工作台

### 端口 8686 被占用

关闭旧的 BossHunter 实例，或使用其他端口：

```bash
bosshunter web --port 8687
```

### 提示已有任务运行

工作台只允许一个高风险后台任务处于活动状态。等待当前任务完成，或通过界面正常停止；不要启动多个服务绕过限制。

### 页面与源码不一致

开发者可重新构建已提交的前端产物：

```bash
cd src/bosshunter/web/frontend
npm ci
npm run build
```

普通用户应先确认代码已完整更新，不需要日常执行前端构建。

### 局域网访问返回 401

绑定非回环地址时需要设置 `BOSSHUNTER_AUTH_TOKEN`，客户端请求还需携带 Bearer Token。默认本地地址 `127.0.0.1` 不需要此设置。

## 8. PDF 与简历

- 确认 `profile.resume_path` 指向有效的 Markdown 文件。
- 确认 `resume_output_dir` 可写。
- 头像不存在时关闭 `resume.show_avatar` 或修正 `avatar_path`。
- 默认渲染失败时可安装 `python -m pip install -e ".[pdf]"`。
- 生成成功后仍需人工检查事实、联系方式、页数和排版。

## 9. 提交 Issue 前

请提供：

- 操作系统、Python、Node.js 和浏览器版本。
- BossHunter 版本或 Git commit。
- 可复现的最少步骤。
- 完整错误堆栈（删除 API Key、数据库密码、姓名和联系方式）。
- 若涉及页面变化，提供已打码截图。

不要上传 `config.yaml`、`.env`、真实简历、数据库、`data/browser-profile/` 或完整聊天记录。
